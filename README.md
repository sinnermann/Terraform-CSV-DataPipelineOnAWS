# 📊 Serverless CSV Data Pipeline on AWS (Terraform + S3 + Lambda + Glue + Athena)

An automated, event-driven serverless ETL data pipeline provisioned entirely with **Terraform**. Uploading a raw CSV file to S3 automatically triggers Python 3.13 data cleaning via AWS Lambda, schema discovery via AWS Glue Crawlers, PySpark aggregation via AWS Glue ETL, and SQL analytics via Amazon Athena—all orchestrated and verified directly from VS Code.

---

## 🏗️ Step-by-Step Pipeline Process (How It Works)

### Phase 1: Infrastructure Provisioning (`terraform apply`)

Terraform automatically builds and connects all required AWS resources in `us-east-1`:

1. **3 Private S3 Data Lake Buckets (`s3.tf`):**
   - **Raw Bucket (`<prefix>-raw`):** Landing zone for incoming raw CSV files.
   - **Processed Bucket (`<prefix>-processed`):** Stores cleaned CSV files and hosts our PySpark ETL script under `scripts/`.
   - **Final Bucket (`<prefix>-final`):** Stores the aggregated summary CSV under `summary/` and Athena query results under `athena-results/`.
2. **Least-Privilege IAM Roles (`iam.tf`):**
   - `csv-pipeline-lambda-role`: Scoped strictly to read from the Raw bucket, write to the Processed bucket, and log to CloudWatch.
   - `csv-pipeline-glue-role`: Scoped strictly to crawl/read/write the Processed and Final buckets and update the Glue Data Catalog.
3. **Serverless Compute & Event Trigger (`lambda.tf`):**
   - Automatically zips `lambda/clean_raw_csv.py` using Terraform's `archive_file` data source and deploys a **Python 3.13** Lambda function.
   - Attaches an S3 `ObjectCreated` event notification (`filter_suffix = ".csv"`) so uploading any `.csv` file to the Raw bucket triggers Lambda immediately.
4. **Data Catalog, Crawlers, ETL Job & Athena Workgroup (`glue_athena.tf`):**
   - Creates the `csv_sales_db` Glue Data Catalog database, two On-Demand Glue Crawlers (`processed` and `final`), a cost-optimized Glue ETL job (`2 x G.1X` workers, 10-minute timeout), and a pre-configured Amazon Athena Workgroup.

---

### Phase 2: Automated Pipeline Execution & Verification (`python run_pipeline.py`)

Instead of manually clicking through the AWS Console or installing the AWS CLI, `run_pipeline.py` runs the entire pipeline end-to-end from VS Code using `boto3`:

1. **Upload Raw CSV:** Uploads `data/sales_raw.csv` (containing messy whitespace, missing values, and a cancelled order) to the Raw S3 bucket.
2. **Real-Time Cleaning (Lambda):** S3 triggers `csv-pipeline-clean-raw-csv`, which trims whitespace, converts customer names to Title Case, replaces blank categories with `"Uncategorized"`, removes cancelled or invalid rows, and writes `cleaned_sales_raw.csv` to the Processed bucket.
3. **Schema Discovery (Crawler #1):** Runs `csv-pipeline-processed-crawler` (excluding `scripts/**`) to infer the cleaned CSV columns and register a table in `csv_sales_db`.
4. **ETL Aggregation (AWS Glue PySpark):** Runs `csv-pipeline-summary-etl`, which groups completed orders by `category`, calculates total revenue (`SUM(amount)`) and order count (`COUNT(order_id)`), and writes a single summary CSV to `s3://<final-bucket>/summary/`.
5. **Final Cataloging & SQL Query (Crawler #2 + Athena):** Runs `csv-pipeline-final-crawler` to register the `summary` table, then executes a SQL `SELECT` query via Amazon Athena and prints the final results directly in the terminal.

## 🛠️ Troubleshooting & Engineering Lessons Learned (Errors We Solved)

During development and testing, we encountered and resolved three real-world cloud engineering issues:

### 1. Amazon QuickSight Blocked on the AWS Free Plan

- **Issue:** The original reference architecture used Amazon QuickSight for final visualization, which requires a paid monthly user subscription and is blocked on the credit-based AWS Free Plan (upgrading to a Paid Plan cannot be reverted).
- **Fix:** Replaced QuickSight with **Amazon Athena** configured with an automated S3 query result location (`aws_athena_workgroup`). This allowed full SQL analytics over the final S3 dataset using pennies of Free Plan credits with zero risk of recurring charges.

### 2. Glue ETL Job Failed Due to Table Naming Mismatch (`--TABLE_NAME`)

- **Issue:** On the first automated test run, `csv-pipeline-summary-etl` failed because passing a hardcoded `--TABLE_NAME` argument from Terraform did not always match the exact table name generated by the Glue Crawler when bucket prefixes started with `csv`.
- **Fix:** Removed the hardcoded `--TABLE_NAME` parameter and updated `glue/sales_summary_etl.py` to query the AWS Glue Data Catalog dynamically at runtime via `boto3.client("glue").get_tables(DatabaseName=...)`, automatically selecting the crawled processed table regardless of prefix naming rules.

### 3. Running End-to-End Orchestration Without the AWS CLI Installed

- **Issue:** Running `aws s3 cp` in PowerShell threw `The term 'aws' is not recognized` because the AWS CLI was not installed locally on Windows.
- **Fix:** Built `run_pipeline.py` using Python and `boto3` (`pip install boto3`). The script reads Terraform outputs (`terraform output -raw ...`) dynamically and orchestrates the S3 upload, crawler polling, Glue ETL job monitoring, and Athena SQL verification completely inside VS Code.

## 📂 Repository Structure

```text
├── data/
│   └── sales_raw.csv             # Sample raw sales dataset with messy & cancelled records
├── glue/
│   └── sales_summary_etl.py      # PySpark ETL script for category revenue & count aggregation
├── lambda/
│   └── clean_raw_csv.py          # Python 3.13 S3-triggered CSV validation & cleaning function
├── providers.tf                  # Terraform & AWS/Archive provider setup + default resource tags
├── variables.tf                  # Input variable definitions (aws_region, project_name, bucket_prefix)
├── s3.tf                         # 3 private S3 buckets + automated Glue script upload
├── iam.tf                        # Least-privilege IAM roles and bucket-scoped policies
├── lambda.tf                     # Automated ZIP packaging, Lambda function & S3 upload trigger
├── glue_athena.tf                # Glue database, crawlers, Glue ETL job & Athena Workgroup
├── outputs.tf                    # Outputs generated bucket names and Athena Workgroup
├── run_pipeline.py               # Automated end-to-end pipeline runner & Athena SQL verifier
├── terraform.tfvars.example      # Example variable configuration
└── README.md                     # Project architecture, walkthrough & troubleshooting log
```

## 🚀 Quick Start & Cleanup

1. **Configure your unique bucket prefix:**
   ```bash
   cp terraform.tfvars.example terraform.tfvars
   # Edit terraform.tfvars and set bucket_prefix = "your-unique-prefix"
   ```
2. **Deploy the infrastructure:**
   ```bash
   terraform init
   terraform apply -auto-approve
   ```
3. **Run the pipeline end-to-end and view Athena SQL results:**
   ```bash
   pip install boto3
   python run_pipeline.py
   ```
   **Expected Output:**
   ```text
   === ATHENA FINAL RESULTS ===
   category | total_amount | order_count
   Clothing | 535.25 | 3
   Home | 460.75 | 2
   Electronics | 250.5 | 1
   Uncategorized | 120.0 | 1
   ```
4. **Destroy all AWS resources (Clean Up):**
   ```bash
   terraform destroy -auto-approve
   ```
